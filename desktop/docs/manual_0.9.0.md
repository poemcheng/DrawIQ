# DrawIQ 0.9.0 操作手冊

先儲存並關閉舊版，再執行 `啟動_DrawIQ_0.9.0.bat`。沿用工作區與帳號。本版是 Python 桌面程式，整合使用者提供的 quote-drawing-extraction Skill 與 Harness 契約。

登入窗會置中並請求前景顯示。黑色啟動視窗會顯示 Python 路徑與開始訊息，初始化失敗時保留原因；紀錄位於工作台資料夾的 `launcher.log`。啟動入口會優先使用工作區 `.venv`，依賴檢查失敗再嘗試 `py -3`，不會改安裝舊部署包。首次工作區需建立管理者，既有帳號可正常登入。

## 三欄與人工覆核

左側保存全部已取得的文字、尺寸、符號、工程欄位與不同方法的候選。中央顯示原始工程圖與實測框。右側自動帶入有來源支持的耐落 16 欄，維持待覆核。方法說明在查詢畫面，不擠入主畫面的工程候選。

1. 匯入 PDF／JPG，或載入既有成果。舊成果可補充規則與工程語意索引；要重跑本版 OCR／工程區塊重讀，按「解析本頁」。
2. 單擊右側選目標，雙擊內容或按「定位／修正」回到來源。左側與右側引用同一筆資料，修改與確認同步。
3. 缺項按「找候選」搜尋全部原文，定位後帶入；或「框選補入」裁圖 OCR，修改值、單位與原文後套用。
4. 對照原圖後按「確認報價 → 下一欄」。圖上沒有的商務資訊可新增補填並設定未提供／不適用；辨識不清則保留待判定。

原有選取、移框、縮放、旋轉、框選辨識、批次確認、排除／復原與操作軌跡均保留。自動帶入與規則通過不代替人工覆核；已經人工改寫、確認或明確取消帶入的內容不由新規則覆蓋。

## 工程圖與報價欄位的角色

- `Full Thread` 與附近完整螺紋標註可帶入規格，接受工程圖的小數逗號，保留原文；不推算螺栓長度。
- Threadlock 下的 Tuflok／明示 precote 或 Loctite 產品辨識為膠別；Nylon 塗膠材料與零件基材分開。替代膠種選項不當成已選定產品。
- 品質彙整保留「首批需附」「每批需附」條件。不同負載、鎖緊／鎖入／破壞／鬆脫扭力分成不同工程要求，數值、單位與上下限各自保存。
- 詢價單有唯一圖頭公司、明確詢價標題及耐落收件人時，可帶入詢價發出方作客戶角色推定；提示明示推定及三處證據，請確認交易角色。
- 收件人、設計責任、客戶料號、年度量、詢價日期、鍍層黑色、強度等級分別保留工程角色，不能直接當客戶名稱、本次量、報價日期、膠色或基材。
- 同值不同日期／小數格式不製造衝突；不同對象、數字、單位、幣別或分母仍需人工選擇。標籤修復只限已辨識的欄位用途，不改寫名稱或數字。
- 模型自寫的證據不能自行證明其值。沒有同位置實測文字支持的模型候選仍在左側，需框選重讀或人工確認。

## 新增 Skill 規則如何使用

`quote-drawing-extraction` 先區分報價標籤、工程圖及不明文件，再依實際欄位標籤與相鄰位置擷取。原值、空白、符號、方法、頁碼、框與不同候選保留，可在「辨識方法／模型／驗證／學習紀錄」查詢。原始套件的來源及差異見 [Skill 整合說明](skill_harness_integration_0.9.0.md)。

這些情況需要對照原圖：

- **報價單號**：`KH` 加八位數是套件樣本格式；其它格式可保留候選並提示異常，不因此改掉合法單號。
- **膠別**：`precoat 80-8(紅)` 與 `precoat 80(紅色)` 是不同產品級別；不因顏色相近合併。`precote` 與 `precoat` 原字樣也保留。
- **螺紋與公差**：`M8x1.25-6h` 的 `6h` 是公差，不是長度；`M10-6g` 不假設螺距。`M6x1,0-6g` 可解析螺距 1，原逗號仍保留。
- **長度單位**：`7/16-20UNCx25.4` 的尾端長度沒有單位證據時，保留未知。公制標籤的 mm 約定會明示來源；工程圖中沒有證據的單位不套用這個約定。
- **數量與單價**：`M`／`K` 不自行當成米或千件；只有 `/ TWD / M` 而沒有金額時，價格維持空值，不能算出單件價。
- **日期**：無效日曆日期、報價有效日早於報價日，保留原文並轉待判定；不猜修正數字。
- **低分與衝突**：來源分數低於 0.8、缺分數、不同原值或不同來源用途會進入覆核清單。分數是辨識程序的分數，不是正確率或已簽核證明。
- **沒有來源框**：提供的 OCR JSON 若缺框或頁面尺寸，原文仍可查詢，但不產生假框位；需回到原檔補框或人工核實。

同一份標籤與工程圖不以檔名、檔序或相似尺寸自動配對。必須有正式對應或人類明確指定的關係；本版機器紀錄的關係欄位不推論配對。

## 方法、模型與框選重讀

中央下方「辨識方法／模型／驗證／學習紀錄」可查實際模型、OCR、耗時、方法狀態、原始回應、規則與追蹤目錄。

PDF 字層與實際圖片區域並讀，避免只有可讀頁尾時漏掉掃描主體。正式工作程序固定使用本機 PP-OCRv6-small ONNX。工程頁最多重讀 8 個已測得的文字區塊，精確映回原圖，保留各次讀文與框。混合 PDF 的 OCR 失敗會保留字層並顯示未完成。

本機視覺模型透過 Ollama 實際能力查詢列出，最多選四個。只在已測得、尚未解決或低信心的區塊內補讀時，裁圖範圍與原圖定位會保留；找不到可追溯範圍的項目轉人工處理。模型的新讀文作為額外候選，不覆蓋原 OCR，也不能把整張圖的猜測當框選證據。

每頁最多提出三個候選裁圖範圍，每次分析每頁最多補讀一區；範圍由實測文字框決定，沒有未解區塊時顯示 `not_needed`。方法紀錄保存裁圖 `vlm_crop.png`、原圖座標與來源 IDs。

每模型／每頁完整模式最多 120 秒，快速模式 30 秒；模型與 OCR 沿用工作程序時間預算，可取消。失敗或超時會保留先前已取得的候選，需檢查方法狀態與未完成頁面；不宣稱一次取得所有文字、符號或尺寸。

## 人工修正如何改善辨識

人工確認且原文、用途仍有效的例子可用於同租戶候選排序；有角色警告的指定來源不進入有效學習例。框選、移框、修正、套用／取消與覆核軌跡仍可匯出。典型錯誤可提升為 Harness 回歸案例，以後修改規則時重播。

這是候選排序、有效人工案例與規則回歸的改進。本版沒有自動重訓 OCR／VLM 神經網路權重；方法查詢會區分已有程序、這次有實際執行的模型與純規則投影。

## 匯出與機器覆核清單

既有匯出包保留原始檔、標註圖、16 個報價欄位、候選、方法、人工軌跡及 Harness 檢查。新增 Skill record、`results.jsonl`、`review_queue.jsonl` 與 `summary.json`，可交由其它程序讀取。

每份 record 保存 document ID、文件版本、來源 hash、原值與正規化、來源頁／框／原文／方法／分數、不同候選及問題。`human_reviewed` 與原人工 status 分開保存；匯出不新增核准或提升分數。缺值是 JSON null，空白單價的原單位片段另外保留。

覆核清單包含缺值、低分、衝突、單位未定、不明文件與來源框缺失，並提供連結的來源 IDs。不同文件依 ID 與 hash 保存，不因同名檔案覆寫或配對。批次只包含這次指定的文件，輸出失敗會回復舊批次；summary 的 artifact hashes 可檢查完整性。

提供 OCR JSON 的資料會明示 `provided_transcription` 與 `ocr_executed=false`；JSON snapshot 的 hash 不當作原始照片的 hash，也不聲稱這次已重新跑過 OCR。

已提供 OCR JSON 可直接重播規則與產生獨立批次，不執行 OCR 或模型。先進入工作台資料夾，再指定單一 JSON 或 JSON 資料夾：

```powershell
cd DrawIQ_Workbench
python tools/run_quote_skill.py --input "vendor/quote_drawing_skill_harness_v0_1/quote_drawing_skill_harness/examples/ocr_quote_01.json" --output "exports/skill_batch"
python tools/run_quote_skill.py --input "vendor/quote_drawing_skill_harness_v0_1/quote_drawing_skill_harness/examples" --output "exports/skill_batch"
```

兩個命令依序執行時，第二次批次包含三個 example；不把前次內容當新增文件累積。輸入框位、分數、頁碼或 document ID 不符合契約時，整批拒絕並保留原輸出，命令回傳非零退出碼。這些 example 是原包人工轉寫，不能當成剛完成的照片 OCR。

## 驗證與已知限制

執行 `驗證_DrawIQ_0.9.0.bat` 或 `python tools/run_harness.py --suite full`。版本指紋、規則案例與測試日誌另存 `qa/harness_0.9.0`。程式或案例改變後，舊報告顯示過期。

Skill 契約驗證（原始驗證工作區：`qa/quote_skill_0.9.0/verification_report.json`） 使用三份原包人工轉寫、獨立工程語法與來源契約案例；它驗證規則及輸出，不是七張真實工程圖的完整 GT，也不是全圖識字率。[0.8.0 歷史來源比較](accuracy_results_0.8.0.md) 保留原次測試指紋，不當作這次已重跑 OCR 的結果。

真實「三張標籤＋七張工程圖」逐欄、逐框 GT 尚未提供，機器 summary 的 precision、recall、exact match 因而維持 null。受損標準號仍須人工核對，不用既知標準號猜補數字。人工核准、排除、稽核與已發布快照仍保留。
