先儲存並關閉舊版，再執行 `啟動_DrawIQ_0.8.0.bat`。沿用工作區與帳號。本次更新為 Python 桌面程式。

## 三欄與人工覆核

左側保存全部已取得的文字、尺寸、符號、工程欄位與不同方法的候選。中央顯示原始工程圖與實測框。右側自動帶入有來源支持的耐落 16 欄，維持待覆核。

1. 匯入 PDF／JPG，或載入既有成果。舊成果補充工程語意索引；要重跑本版 OCR／工程區塊重讀，按「解析本頁」。
2. 單擊右側選目標，雙擊內容或按「定位／修正」回到來源。左側與右側引用同一筆資料，修改與確認同步。
3. 缺項按「找候選」搜尋全部原文，定位後帶入；或「框選補入」裁圖 OCR，修改值、單位與原文後套用。
4. 對照原圖後按「確認報價 → 下一欄」。圖上沒有的商務資訊可新增補填並設定未提供／不適用；辨識不清則保留待判定。

原有選取、移框、縮放、旋轉、框選辨識、批次確認、排除／復原與操作軌跡均保留。自動帶入不代替人工覆核。

## 本版對應規則

- `Full Thread` 與附近完整螺紋標註可帶入規格，接受工程圖的小數逗號，保留原文；不推算螺栓長度。
- Threadlock 下的 Tuflok／明示 precote 或 Loctite 產品辨識為膠別；Nylon 塗膠材料與零件基材分開。替代膠種選項不當成已選定產品。
- 品質彙整保留「首批需附」「每批需附」條件。不同負載、鎖緊／鎖入／破壞／鬆脫扭力分成不同工程要求，數值、單位與上下限各自保存。
- 詢價單有唯一圖頭公司、明確詢價標題及耐落收件人時，可帶入詢價發出方作客戶角色推定；提示明示推定及三處證據，請確認交易角色。
- 收件人、設計責任、客戶料號、年度量、詢價日期、鍍層黑色、強度等級分別保留工程角色，不能直接當客戶名稱、本次量、報價日期、膠色或基材。
- 同值不同日期／小數格式不製造衝突；不同對象、數字、單位、幣別或分母仍需人工選擇。標籤修復只限已辨識的欄位用途，不改寫名稱或數字。
- 模型自寫的證據不能自行證明其值。沒有同位置實測文字支持的模型候選仍在左側，需框選重讀或人工確認。

## 方法與模型

中央下方「辨識方法／模型／驗證／學習紀錄」可查實際模型、OCR、耗時、方法狀態、原始回應、規則與追蹤目錄。

PDF 字層與實際圖片區域並讀，避免只有可讀頁尾時漏掉掃描主體。正式工作程序固定使用本機 PP-OCRv6-small ONNX。工程頁最多重讀 8 個已測得的文字區塊，精確映回原圖，保留各次讀文與框。混合 PDF 的 OCR 失敗會保留字層並顯示未完成。

本機視覺模型透過 Ollama 實際能力查詢列出，最多選四個。每模型／每頁完整模式上限 120 秒，快速模式 30 秒；OCR／局部重讀沿用既有程序時間預算，可取消。VLM 每次最多補八項，失敗保留 OCR，不宣稱一次取得所有字元。

人工確認且原文、用途仍有效的例子可用於同租戶候選排序；有角色警告的指定來源不進入有效學習例。框选、移框、修正、套用／取消、覆核軌跡仍可匯出。本版沒有重訓 OCR／VLM 神經網路權重。

## 驗證與已知限制

執行 `驗證_DrawIQ_0.8.0.bat` 或 `python tools/run_harness.py --suite full`。版本指紋、規則案例與測試日誌另存 `qa/harness_0.8.0`。程式改變後舊報告顯示過期。

實際來源欄位比較見 [準確度驗證](accuracy_results_0.8.0.md)，完整模組盘點見 [架構盤點](accuracy_architecture_audit_0.8.0.md)。測試通過不是全圖識字率；受損標準號仍須人工核對，不用既知標準號猜補數字。

既有人工值、已確認內容、排除、稽核與發布快照保留。未確認的機器品質彙整可補回批次條件；人工直接改寫的彙整保持原值。匯出仍包含原檔、標註、16 欄、方法、候選、軌跡與 Harness 檢查。
