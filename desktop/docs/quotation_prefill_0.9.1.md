# DrawIQ 0.9.1：先帶入最佳候選，再人工覆核

本版依使用者的流程，先把可用的最佳候選放到右側，讓人直接對照中央工程圖確認。右側的 16 個內容格都有值或明確的補填提示；提示不會變成報價事實。左側仍保留全部候選與原始擷取資訊。

## 畫面上的狀態

有明確且符合目前欄位用途的來源，沿用既有自動帶入。可信條件不足但有適合候選時，先顯示候選值，標示「建議／待確認」；有不同原值或衝突時，標示「衝突／待確認」。可以定位所選來源，也可以從左側或其它候選換來源。

候選選擇考慮欄位用途、原圖來源與既有判定結果。排序分數只用於選擇建議；來源的 OCR 分數、衝突、未知單位及角色警告仍保留。圖面沒有的報價單號、專案代號、報價人員、報價日期、有效日、數量或金額等商務資料，顯示補填提示，不建立假數字或日期。

工程用途仍需區分：螺紋／規格引用其實際工程標註；詢價日期不能代替報價日期；收件人或設計責任不能代替客戶名稱；Nylon 塗膠材料不能代替基材；鍍層的黑色不能代替膠色。無法解析的標準號保留 OCR 字樣供重讀，不能猜成另一個標準。圖頭的製程代號保留為工程候選，對用途不確定的建議需人工判定。

沒有適合候選的格子會顯示「請補填」等操作提示。已明確取消帶入的欄位保留取消結果。既有人工改寫、確認、核准與發布快照沿用，不因打開工作台重新套用建議。

## 人工確認的流程

1. 匯入 PDF／JPG 或載入既有成果，先查看右側已帶入的建議與缺項。
2. 選取右側欄位並定位來源，確認中央圖上的原文、符號、尺寸、單位及適用對象。
3. 不正確時按「找候選」，從左側原文或工程候選換來源；圖上仍漏字則「框選補入」重讀並修改。
4. 修改值、單位、原文或用途後套用。內容或來源處於衝突／待判定時，先判定或改正，再按「確認報價 → 下一欄」。
5. 圖上確實沒有的資料由人補填，或明確設為未提供／不適用。人工確認完成後，再核准或輸出。

建議帶入只建立供覆核的選擇，不新增人工核准，也不提升 OCR 分數。人類實際選來源、框選、修改與確認仍由既有稽核與學習程序記錄；只有仍有效的人工確認可用於候選排序，沒有自動重訓神經網路權重。

## 程式與匯出契約

`quotation_rows(doc, include_proposals=False)` 保留嚴格來源驗證；桌面右側與 machine record 使用 `include_proposals=True` 顯示／保存建議。`source` 可以是待確認的候選，必須同時讀取 `proposed`、`status` 及問題；不能只因 `source` 非空就當成自動通過。

新增的 row 資訊包括 `proposed`、`proposal_score`、`proposal_confidence`、`proposal_reason`、`proposal_issues`、`proposal_alternatives` 與 `display_value`。`display_value` 是畫面用字，不能直接寫入事實欄位。

`drawiq-skill-record/0.9.1` 每欄保存：

- `raw`、`normalized`、`sources`、`confidence`：實際候選值、結構化值與原圖來源；confidence 保持來源程序原分數。
- `proposed`、`selected_proposal`、`proposal_issues`：被選候選 ID、排序分數、排序估計、選擇原因及待確認問題。這些分數不代表正確率或人工核准。
- `alternatives`：其它原值與實際來源；替代候選只能引用這份文件中的 requirement／region IDs，不能用生成的文字自行建立證據。
- `review_status`、`support_verified`、`original_human_reviewed`：原本的人工覆核事實，完整保留。
- `human_reviewed`：建議值不新增人工覆核；只有原本 verified、來源支持仍有效且沒有新問題的情況，保留原有的人工覆核表示。

建議的 machine `status` 維持 `needs_review` 或 `conflict`。沒有實值的 `raw`／`normalized` 是 null，machine `status` 仍是 `missing`；畫面的補填提示不匯入這些欄位。覆核清單保存所選建議與其它來源 IDs，方便定位修正。

批次輸出保留 ID hash 檔名、獨立批次、原子替換與失敗回復。同 document ID 的我方 0.9.0 record 可更新為 0.9.1；不同文件或未識別檔案仍不得覆寫。原始檔 hash、人工轉寫 snapshot hash、模型執行與純規則重播仍分開，不以檔名或相似尺寸推定跨文件配對。

## 驗證範圍

本次需驗證右側先帶入、衝突／低分提示、所選來源定位、缺項提示、人工清除保留與匯出狀態分離。既有嚴格 Harness／GT 檢查仍檢查可信自動來源；增加建議覆蓋數不等於辨識正確率增加。

執行 `python tools/run_harness.py --suite full` 取得本版本指紋與測試日誌。完整「三張標籤＋七張工程圖」逐框、逐欄 GT 尚未提供，機器 summary 的 precision、recall、exact match 維持 null。實際測試結果以當次報告指紋為準。
