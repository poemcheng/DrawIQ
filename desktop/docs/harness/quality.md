# 品質、證據與已知限制

## 可機械驗證

- 核心不直接匯入 GUI／HTTP，必要架構與契約文件存在。
- 固定標註案例驗證客戶角色、年度量、ISO 數量、塗膠／基材、螺紋、金額、日期、衝突與框格式。
- 案例包含正例與反例；通過也包括「正確拒絕錯誤來源」，不表示反例內容被採用。
- 回歸測試在暫存工作區執行；覆核、原子回滾、原文支持、軌跡、學習退出與不可變發布已有測試。
- 標註案例重播不執行 OCR／VLM；部分單元測試會呼叫合成图辨識或模擬模型，測試總數不是實圖識字準確率。
- 每次記錄程式與案例 SHA、政策 SHA、Python／平台、測試日誌與日誌雜湊；開始和結束程式指紋須相同。
- 查詢最新報告會檢查完整性與目前程式指紋；過期報告不能顯示為目前版本已驗證。

## 人工回饋成為案例

先核對原圖並確認右側欄位，再在「辨識方法／模型／驗證／學習紀錄」匯出目前欄位的回歸案例。內容修改後若已失去確認，禁止匯出為已確認案例。

可用 `--cases` 重播該檔；若要加入固定回歸集，審查匿名化、預期用途、原文支持，再合併到 `evaluation/harness_cases.json`，不要把未確認模型輸出當標註答案。

## 待處理與限制

0.8.0 已加入三個固定來源的明示報價欄位比較，詳見 [實際來源評估](../accuracy_results_0.8.0.md)。這個小型集合與完整逐字／逐符號標註不同；未知圖面仍須人工覆核。

- 尚未建立具完整人工逐字／逐符號標註的實圖測試集；不報完整識字準確率。
- VLM 每次優先補最多八個項目，未完成範圍需補讀或人工覆核。不同本機模型可能逾時或回傳錯誤格式。
- 已確認上下文模型改善候選排序；未自動訓練 OCR／VLM 權重。
- AST 規則針對列出的核心模組，不宣稱整個舊系統已完成嚴格分層或動態依賴分析。
- 程式指紋涵蓋 app 模組、測試、驗證工具、固定案例及核心治理文件，不涵蓋整套第三方模型權重或運行電腦的所有檔案。
- 本機 SHA 鏈與報告只能檢測不一致，沒有宣稱可抵抗擁有整個工作區寫入權限的人。
- 此版本是 Python 桌面程式與驗證工具；沒有重建 EXE 安裝器。
